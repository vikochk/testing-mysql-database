# v.kochneva. MySQL Database Automation.

Репозиторий содержит проект автоматизации и интеграционного тестирования реляционной базы данных MySQL с использованием ORM-библиотеки SQLAlchemy.

Проект демонстрирует работу с базой данных на основе паттерна Data Mapper, включает в себя симуляцию запусков автотестов через специализированную мок-утилиту, ведение сессий прогонов, логирование и автоматическое управление транзакциями при прохождении тестов.

---

## Как запустить проект
1. Клонировать репозиторий:

```bash
git clone https://github.com/vikochk/testing-mysql-database.git
cd <project_folder>
```

2. Подготовить базу данных:
* Разверните локальный сервер MySQL.
* Создайте базу данных с именем union_reporting в кодировке utf8mb4 на основе дампа БД (dump.sql).
* Восстановите базу данных из вашего файла дампа через командную строку:
```bash
mysql -u root -p union_reporting < "dump.sql"
```

2. Установить Python 3.11+.

Если используется pyenv:

```bash
pyenv install
```

3. Создать виртуальное окружение:

```bash
python -m venv .venv
source .venv/bin/activate    # Linux/macOS
.venv\Scripts\activate.bat   # Windows
```

4. Установить зависимости:

```bash
pip install -r requirements.txt
```

5. Настроить тестовые данные и подключение:

В папке tests/resources/ найдите файл конфигурации БД config.json и укажите в нем параметры подключения к вашей БД. Пример содержимого файла:
```
{
    "db_username" : "root",
    "db_password" : "password",
    "db_host" : "localhost",
    "db_port" : "3306",
    "db_name" : "union_reporting"
}
```

В файле с тестовыми данными test_data.json укажите имя автора, искусственное название проекта с автотестами и количество обрабатываемых дубликатов. Пункт new_tests_names позволит выбрать собственные имена для тестов, которые будут созданы в БД в ходе тестов. Пункты author_login и author_email являются необязательными и могут быть сгенерированы в ходе работы программы. Пример содержимого:

```
{
    "author_name" : "Vika",
    "project_name" : "LearningDB",
    "amount_of_tests_with_duplicates" : 5,
    "new_tests_names" : {
        "summation": "KS-12345 Checking the summation of two numbers",
        "multiplication": "KS-67890 Checking if a string is multiplied by a number"
    },
    "author_login" : "vikoch",
    "author_email" : "vikoch@gmail.com"
}
```

6. Запустить инструменты проверки и тесты: 
* Проверить качество кода линтером (Ruff):
```bash
ruff check .
```
* Автоматически отформатировать стиль кода:
```bash
ruff format .
```
* Запустить автотесты:
```bash
python -m pytest tests`
```

## Реализованные тесты

### Тест-кейс 1. Добавление новых записей (test_add_test.py)

Сценарий проверяет корректность сохранения результатов прогона новых тестов «с нуля»:

* Шаг: имитирует прогон тестов с помощью MockTestRunner (генерирует случайные статусы, браузеры, точное время начала/окончания до секунд и имя хоста выполнения).
* Постусловие: сохраняет результаты в таблицу test через метод create_test. Система автоматически связывает запись с нужным автором, проектом и сессией (создавая их в БД, если они отсутствовали).


### Тест-кейс 2. Обработка тестовых данных (test_redact_tests.py)

Интеграционный сценарий, проверяющий выборку, клонирование, обновление информации и последующую очистку данных:

* Предусловие: извлекает из базы данных все тесты. Фильтрует их по критерию: ID теста содержит повторяющиеся цифры (например, 11, 333). Выбирает случайные 5 записей и делает их физические копии (copy_test) с привязкой к текущему проекту и автору.
* Шаги: для каждой скопированной записи имитирует новый запуск через MockTestRunner и выполняет обновление записи на месте (update_test через SQL UPDATE), заполняя её результатами прогона. Верифицирует успешность сохранения новых параметров.
* Постусловие: удаляет все созданные в ходе теста копии из базы данных (delete_test), проверяя успешность удаления, чтобы гарантировать неизменяемость исходного дампа БД.
